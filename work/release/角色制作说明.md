# 桌宠便签角色制作工具包

把这个 ZIP 和角色描述或参考图交给 Codex。请它解压并读完本说明，最后交付一个通过校验的角色 ZIP。打开桌宠便签的「桌宠设置」，点击「导入角色 ZIP」或把角色 ZIP 拖进窗口。在预览中选择「安装并使用」。遇到相同 ID 时，可以选择「更新并使用」或「另存为新角色」。

可直接复制[小宠物制作指令](小宠物制作指令.md)里的提示词，并把括号里的内容改成自己的角色需求。

## 新作素材

有图像生成能力时，先定稿一张透明背景的角色设定图，再以同一张图为参考生成各动作帧，保持头身比、配色、线条粗细、光照、位置和视角一致。图集中的角色保持完整四肢和带抗锯齿的透明边缘，每帧使用同一基线，左右走保持同一地面高度。逐帧预览，清理闪动、残影、意外的背景和水印。

只有代码能力时，可用 Pillow 从用户提供的透明 PNG 或 WebP 拆分、对齐和拼图。素材不足时先说明哪些动作缺少，可把一帧用于对应行做兼容占位，同时告知用户该动作只有静态图。请使用有权使用和分享的素材。

## ZIP 格式

包内只有两份文件，直接放根目录，或同放在一层目录。

- `pet.json` 是 UTF-8 JSON。必填 `id` 和 `displayName`，可填 `description` 与 `spritesheetPath`。ID 以小写英文字母开头，后续使用小写字母、数字、连字符或下划线，最长 48 字符。显示名最长 40 字，说明最长 160 字。
- 透明 RGBA 图集为 PNG 或 WebP，推荐无损 WebP。每格为 192 × 208 像素，8 列 × 9 行，总计 1536 × 1872。也接受 1536 × 2288 的图集，读取前 9 行。每行从第 1 列起连续放动画帧，后面的空格全透明。每行第一格要有可见素材。
- ZIP 及解压文件总量分别上限 24 MiB。普通角色 ZIP 内只放素材与清单。

```json
{
  "id": "my-pet",
  "displayName": "我的桌宠",
  "description": "由参考图制作的桌面宠物",
  "spritesheetPath": "spritesheet.webp"
}
```

| 行 | 当前动作 | 播放速度 |
|---|---|---|
| 1 | 待机 | 6 fps |
| 2 | 向右移动 | 10 fps |
| 3 | 向左移动 | 10 fps |
| 4 | 挥手或点击回应 | 8 fps |
| 5 | 跳跃 | 10 fps |
| 6 | 失落 | 3 fps |
| 7 | 等待，可表现困倦 | 10 fps |
| 8 | 忙碌，保留用于角色动作预览 | 6 fps |
| 9 | 查看或好奇 | 8 fps |

## 1.2.0 扩展格式

角色要支持 1.1.x 时，使用上面的旧格式。只面向 1.2.0 或以上，可以在清单中添加 `"schemaVersion": 2`、`frameSize` 和 `actions`。扩展格式仍然只需要清单和一张带透明背景的 PNG 或 WebP，24 MiB 上限相同。

- `frameSize` 可填 `[192, 208]` 或 `[384, 416]`。图集按整格排列，最多 16 列，像素总量上限 2400 万。用实际需要的最多帧数决定列数。
- 每个动作声明 `row`（从 0 开始）、`frames`（从第一格连续占用的帧数）、`fps`（1 到 24 的整数）。待机须为第 0 行，每个动作占一行。每行用完的格子全部透明。
- 九个基础动作均须声明。缺少素材时可先放透明背景的单帧角色，保持各行首帧有可见素材。下例使用 8 列 × 10 行和 384 × 416 的格子，图集为 3072 × 4160 像素。

```json
{
  "id": "my-pet",
  "displayName": "我的桌宠",
  "spritesheetPath": "spritesheet.webp",
  "schemaVersion": 2,
  "frameSize": [384, 416],
  "actions": {
    "idle":       {"row": 0, "frames": 6, "fps": 6},
    "run_right":  {"row": 1, "frames": 8, "fps": 10},
    "run_left":   {"row": 2, "frames": 8, "fps": 10},
    "waving":     {"row": 3, "frames": 8, "fps": 10},
    "jumping":    {"row": 4, "frames": 8, "fps": 10},
    "failed":     {"row": 5, "frames": 4, "fps": 3},
    "waiting":    {"row": 6, "frames": 6, "fps": 8},
    "running":    {"row": 7, "frames": 6, "fps": 6},
    "review":     {"row": 8, "frames": 6, "fps": 8},
    "petting":    {"row": 9, "frames": 8, "fps": 10}
  }
}
```

| 可选动作 | 触发方式 | 制作要点 |
|---|---|---|
| `petting` 摸头 | 在宠物头部来回移动鼠标 | 轻微歪头、闭眼或蹭手，结束后回到待机姿势 |
| `lifted` 被提起 | 按住宠物拖动 | 可循环，身体悬空时的落点保持稳定 |
| `landing` 放下 | 结束拖动 | 轻落地，最后一帧接近待机首帧 |
| `sleeping` 睡觉 | 一段时间未互动 | 可循环，适合呼吸或尾巴的小幅运动 |
| `waking` 醒来 | 睡着后单击或摸头 | 从睡姿过渡到待机 |
| `stretching` 伸懒腰 | 桌宠自主触发 | 从待机起势，完整收势后回到待机 |
| `celebrate` 庆祝 | 勾完便签里的清单，或喂入纸团 | 播一遍，建议保持身体比例和底部基线 |
| `feed_open` 张嘴 | 纸团在嘴边停留 | 嘴部中心尽量位于横向 51%、纵向 57%，末帧保持张嘴 |
| `feed_ready` 接纸团 | 停留达到投喂时间 | 可以只放一张张嘴姿势，播放到最后一帧会停住 |

从桌宠便签 1.2.2 起，可在 `lifted` 中设置整数 `loopStart`，取值从 0 到 `lifted` 末帧。每次提起都从第 0 帧起播，播到末帧后只循环 `loopStart` 至末帧。若 `loopStart` 大于 0 且角色提供了 `landing`，可在 `lifted` 中设置整数 `earlyLandingFrame`，指向 `landing` 的有效帧。进入循环段前松手时，从该帧播放落地动作。进入循环段后松手时，落地从第 0 帧开始。两项默认值均为 0。

制作烟雾变身时，可让 `earlyLandingFrame` 对应烟雾完全遮住角色的画面。让 `landing` 的第一帧衔接悬空循环，最后一帧衔接待机首帧。已发布的 1.2.1 会从头循环 `lifted`，并从第 0 帧播放 `landing`。

单击回应使用 `waving`。点击、跳跃、摸头、庆祝等短动作在桌面上只播一遍，首尾应接近待机姿势。待机、走路、提起与睡觉的循环动作则需要检查末帧接回首帧时有没有跳动。优先补中间过渡帧，再根据实际动作时长调整帧率。

旧角色包用 `review` 表现摸头，拖动时保持 `jumping` 的中间帧，松开时接播后半段，直到回到待机。

## 校验和打包

示例角色 ZIP 是灰色几何图案，用来验证尺寸、透明边缘和帧顺序。它可以直接导入软件。

```powershell
py -m pip install -r requirements.txt
py pack_character.py .\example.codex-pet.zip
py pack_character.py .\素材目录 .\我的角色.zip
```

最后确认预览和软件安装都能读到角色。请交付角色 ZIP，用户可直接导入。
